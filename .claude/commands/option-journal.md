# option-journal

复盘模拟盘里已结算的期权持仓（Bull Put Credit Spread 和现金担保 Sell Put）：把 `/option-review` 每周存下的建议快照，和每笔持仓最终的盈亏对照，回答"建议准不准"——听"平仓"建议比拿到到期多赚多少、被标"需要关注"的是不是真的出事、"继续持有"后来有没有赢，并用不同阈值重算一遍（what-if）。

**离线、只读、不改账本和快照、不碰 `data/positions.md` / `outputs/` / `wiki/`。** 脚本不联网，只读 `data/paper-trading/spreads.json`（账本）和 `data/paper-trading/reviews/`（快照），只写 `data/paper-trading/` 下的 `journal.md`、`journal.json`、`journal-notes.json`（gitignored，私有）。它不会平仓，也不会改任何阈值。

## Arguments

从仓库根目录运行。生成复盘报告：

```bash
./.venv/Scripts/python.exe scripts/put_journal.py
```

给某笔持仓记一条笔记（可选，只追加；`ID` 是账本里的持仓 id，不在账本里会报错）：

```bash
./.venv/Scripts/python.exe scripts/put_journal.py note ID "文字" [--kind reason|mindset|exit|other]
```

`--kind` 默认 `other`：`reason` 开仓理由、`mindset` 当时的心态、`exit` 平仓或不平仓的原因。笔记只出现在报告的时间线里，不参与任何统计。

## 可比持仓

- 只看**已结算**的持仓（到期结算或提前平仓）。
- 每笔持仓只使用**日期不晚于平仓日（`exit_date`，含当天）**的快照（option-review 只检查未平仓的持仓，所以平仓当天的快照一定是平仓之前拍的）；平仓日之后的建议没法执行，忽略。数据质量为"没有数据"的行（取不到报价、到期当天）也排除。
- 至少有一条这样的快照的已结算持仓才算**可比持仓**。A、B、C 和重算表都只在可比持仓上算；报告头写明"已结算 N 笔，其中有建议可比 M 笔"。
- 陈旧报价（休市时的快照）的行**计入**，不排除，但 A 的明细里标出"陈旧报价"、汇总里写陈旧行数。
- 盈亏为 0 的持仓留在分母里，既不算赢也不算出事。

## 四块统计的口径

**A. 平仓建议值不值得听。** 对出现过"平仓"建议的持仓，取最早的一条。"当时平仓的盈亏" =（开仓权利金 − 那次快照的回购成本）× 100 × 张数；差额 = 当时平仓 − 实际盈亏，正数表示听建议更好。汇总：笔数、平均差额、总差额、听建议更好的笔数。

**B. "需要关注"准不准。** 持仓有任何一条可用快照的建议是"需要关注"就算被标过关注；最终亏损算出事。精确率 = 被标过关注里出事的比例；召回率 = 出事的里被标过关注的比例。另按**首次被标关注的命中规则**（价内/止损，或财报/Delta）分别给精确率。

**C. "继续持有"后来是不是真的没事。** 最后一条可用快照的建议是"继续持有"的持仓里，最终盈利的比例。

**D. 连赢之后。** 用所有已结算持仓（与建议无关），按结算日再按 id 排序（同日结算按 id，仅供参考），统计前面连赢 3 笔之后的下一笔的胜率，并显示全体胜率作对照。样本几乎总是不足，照样显示并带警告。

## What-if 阈值重算

快照里存了重算需要的数字，对每条快照用不同阈值重新跑一遍 `/option-review` 的规则，不重新取行情。

- **平仓阈值（已赚比例）**：0.50、0.60、0.70、0.80（当前）、0.90。对每个值报告：触发"平仓"的持仓数；这些持仓若在最早触发的快照处平仓（只当该快照不晚于实际平仓日才取代实际盈亏），所有可比持仓的总盈亏；与按实际总盈亏的差额。
- **关注阈值（Delta）**：0.25、0.35（当前）、0.45。对每个值报告被标关注数、出事数、精确率、召回率；只替换 Delta 部分，财报触发的关注照常计入。

## 样本规则

每个统计块的第一行写样本数。**可比持仓（D 用已结算持仓）少于 30 笔，报告会写"样本不足，别下结论"。** 刚开始用几乎一定不足 30 笔：报告可以看，数字不能当结论，更不能据此改阈值。没有已结算持仓时，仍会写出一份只有"进行中"部分的报告。

## 报告

每次运行覆盖 `data/paper-trading/journal.md`（文字）和 `journal.json`（机器可读，含各统计的数值和样本数、每笔时间线）。`journal.md` 的结构：

1. 头部：生成日期、已结算 / 可比 / 进行中笔数、快照份数和日期范围，以及读取快照或笔记时的提示。
2. 建议准不准：A、B、C、D。
3. 阈值重算：两张表。
4. 每笔已结算持仓的时间线：各快照一行（日期、建议、规则、已赚比例、Delta、理由、数据质量）、与建议是否一致、笔记。
5. 进行中的持仓：只列已积累的建议数和最近一条，不做判断。
6. 页脚：口径说明、"模拟/研究用途，非投资建议"。

口径提醒：当时平仓用快照中间价，真实平仓有滑点，所以"听建议"的数字偏乐观；一笔持仓约每周一条建议，最早的"平仓"建议可能晚于最佳平仓点。

## 与其他命令的关系

- `/option-review`：每周产生建议并存快照（`data/paper-trading/reviews/`），本命令读这些快照。
- `/spread-sim`、`/put-screen`：开仓、平仓、结算都写同一个账本，本命令只读它；价差和 Sell Put 一起复盘。

## Steps

### 0. Resolve output language

Read `data/config.md` and extract the `lang` field (default `zh`). If `--lang zh|en` was passed, use that. Respond in that language. 脚本输出是中文，如实转述，不要重新计算数字。

### 1. 运行

运行上面第一条命令，生成报告。它不联网，很快。没有已结算持仓时只会提示"还没有已结算的持仓"，仍会写出报告；如实告诉用户并结束。只有铁鹰已结算时提示的是"除铁鹰外暂无已结算持仓（铁鹰见下方铁鹰块）"，这时不要结束，继续第 2 步转述铁鹰块。只有 Call 借方价差已结算时提示的是“除 Call 借方价差外暂无已结算持仓”（见其块），铁鹰和 Call 借方价差都有已结算而没有其他策略时提示“除铁鹰与 Call 借方价差外暂无已结算持仓”；同样不要结束，继续转述它们各自的块。

### 2. 转述结果

1. 转述控制台摘要（已结算 / 可比 / 进行中笔数、快照份数）和任何"提示"（比如快照或笔记文件有问题）。
2. 读 `data/paper-trading/journal.md`，转述"建议准不准"A、B、C、D 四块，**每块都带上样本数和样本不足的警告**；再简述阈值重算两张表。数字照抄，不要自己重算。
   - 报告里有“铁鹰”块（`## 铁鹰`）时也要转述：已结算笔数、胜率、理论盈亏平衡胜率（说明它和按实际盈亏比算的口径不同）、突破情况、总盈亏，带上样本数和样本不足警告。铁鹰不计入 A–D 和阈值重算，也不计入顶部的“已结算 N 笔”；顶部会另写“另有铁鹰已结算 N 笔，见铁鹰块”，照此转述。
   - 报告里有“Call 借方价差”块（`## Call 借方价差`）时也要转述：已结算笔数、赢笔数、胜率、所需胜率（逐笔平均，净支出 ÷ 宽度，说明它和按实际盈亏比算的盈亏平衡胜率口径不同）、赢的笔平均捕获最大收益的几成、总盈亏，带上样本数和样本不足警告。它是买方策略，没有“突破侧”，不计入 A–D 和阈值重算，也不计入顶部的“已结算 N 笔”；顶部会另写“另有 Call 借方价差已结算 N 笔，见其块”，照此转述。
   - 给铁鹰或 Call 借方价差记的笔记只存进笔记文件，报告里不显示（脚本记笔记时会提示）。
3. **可比持仓少于 30 笔时不下结论**：只陈述数字，明确说样本太少，不据此建议改阈值或改变做法。
4. 告诉用户报告路径 `data/paper-trading/journal.md`。
5. 提醒：这只是复盘，是否平仓永远由用户决定；要平仓用 `put_screen.py close ID`（或 `spread_sim.py close ID`）。不要自己执行 `close`。
6. 可选：问用户要不要给某笔持仓记一条笔记；用户说要，才用 `note ID "文字" --kind ...` 记，不要自己编笔记。

## Rules

- 不修改 `spreads.json` 和快照、不平仓、不写 `data/positions.md` / `outputs/` / `wiki/`。
- 金额按每张合约 ×100、中间价成交、不含佣金。
- 模拟/研究用途，非投资建议。
