# strategy-pick

**先选策略**：用户给一个 ticker（和自己的看法），脚本读 wiki 论点、一年日线和期权数据（当前数据源），按固定的七步决策树推荐 **1–2 个**看涨或中性的期权策略，并写出一份逐步算清楚的报告（每一步的输入值、阈值、阈值常量名、结果）。它回答的是"这只票该用哪种策略"，选定之后再用对应的真实命令（`/put-screen`、`/spread-sim` 等）去挑合约。

**Advisory only.** 只读：不下单、不连券商、不写 `data/positions.md`、账本、`wiki/`、`outputs/`；只写私有目录 `data/strategy-picks/<运行日期>-<TICKER>.md` 和同名 `.json`（gitignored，里面有持仓判定与论点看法）。永远不替用户开仓，不替用户选看法。研究用途，非投资建议。

## Arguments

自然语言或显式参数。解析成：

```bash
./.venv/Scripts/python.exe scripts/strategy_pick.py TICKER [--view 看好|中性|不看好] [--class bluechip|hot|etf]
```

| 用户说 | 解析 |
|--------|------|
| "ZZZQ 适合什么策略" | `ZZZQ`（不带 `--view`，看法从 wiki 读） |
| "我看好 ZZZQ，帮我选个策略" | `ZZZQ --view 看好` |
| "ZZZQ 我觉得就是横盘，中性" | `ZZZQ --view 中性` |
| "我不看好 ZZZQ" | `ZZZQ --view 不看好` |
| "ZZZQ 当 ETF 看" / "按热门股算" | `--class etf` / `--class hot`（另有 `bluechip`） |

- `--view` 也接受 `bull` / `neutral` / `bear`。用户明确给的看法**优先于 wiki**；两者不一致时报告会写警告，如实转述。
- `--class` 只在用户明确要改类别时才加；不加则按 wiki 档位、ETF 赛道表等自动判定。
- ticker 只能是字母、数字、点和连字符，最长 10 位。参数错误退出码 2：把报错给用户看，改正后重跑。

## 退出码

| 码 | 含义 | 写文件？ |
|----|------|----------|
| 0 | 完成。**包括**门槛出局、不看好、历史不足一年——这些都写文件，结论是"不做期权建议"之类 | 写 `.md` + `.json` |
| 1 | 数据源或行情失败，或缺必要数据（如"找不到合约"） | 什么都没写 |
| 2 | 参数错误 | 什么都没写 |
| 3 | 没有可用的论点，需要用户给看法 | 什么都没写 |

## Steps

### 0. Resolve output language

Read `data/config.md` and extract the `lang` field (default `zh`). If `--lang zh|en` was passed, use that. Respond in that language. 脚本输出是中文；忠实转述，**不要自己重算数字**。

### 1. Run

按上面的解析跑一次脚本。**Data source:** 期权数据来自当前数据源（`ibkr` / `yahoo` / `demo`，设置与质量见 `docs/option-data-sources.md`；报告开头写明来源和数据质量，原样转述），财报和除息日一律来自 Yahoo。IBKR 模式是只读延迟数据，休市时是延迟冻结的上一交易日数据，报告按行情快照日标注，网关设置在 `data/ibkr.env`（gitignored），never print or commit the values。

### 2. 按退出码处理

**退出码 3（需要看法）**：脚本会打印提示，说明 wiki 里没有这只票可用的论点（没有 thesis、状态是 under_review 或无法识别）。**把问题原样问给用户**：对 ZZZQ 你看好、中性还是不看好？然后用 `--view` 带上他的回答重跑。**绝不替用户选看法**，不要从语气、价格走势或自己的判断猜。

**退出码 0（完成）**：读 `data/strategy-picks/` 里刚写的 `.md`（控制台摘要里有路径），然后转述：

0. **路径图**：控制台有 `路径图：<路径>` 一行时，把路径告诉用户，说明它就是报告顶部那张决策路径图（同名 `.svg`），问用户要不要打开；用户同意后，在浏览器面板打开本地 `file:///` 路径。图只在本地看：不发布、不上传，不要发布成 Artifact，也不要拷进 `wiki/` 或 `outputs/`。不要从图上读数复述，数字以报告为准。控制台（或 stderr）出现 `路径图生成失败（…）` 时如实转述，并说明报告不受影响，照常写好了。

1. **结论**：叶子（看法 × 持有 × 走势 × IV 位置）、**两个推荐（或一个）**及排名、每个推荐的 Delta 区间、参考价位、下一步命令。参考价位是线性近似，标"粗略"，用 1σ 预期波动算；IV 缺失时不给。
2. **所有警告，一条不漏，措辞不淡化**。尤其这几类要原样讲：
   - **权利金薄**（IV 低或低于类别阈值）：小仓位或等 IV 回升。
   - **论点过期**（thesis 超过期限未更新）和 **看法冲突**（用户指定与 wiki 状态不一致）。
   - **"代理"**：IV 位置是代理——平值 IV 对自己过去一年的 21 日实现波动率分布做百分位，不是真正的 IV Rank / IV 百分位（数据源没有 IV 历史）；IV 缺失时退到实现波动率自比，是再退一步的代理。**±15% 内行权价个数是全链合并计数，也是代理**，可能多算。
   - 财报：热门股到期日必须早于财报日，财报在 7 天内第一推荐会变成"等财报后再看"；日期未知也要警告。ETF 看除息日。
   - 历史不足一年、数据缺口、持股不足 100 股（备兑 Call / Collar 做不了，改走未持有分支）、`data/positions.md` 不存在（视为未持有）、没有期权数据（门槛出局）。
3. **组合占比标记**：现金担保 Put 或 Bull Put 排名由"参考行权价 × 100 占组合约 x%"和类别决定。报告里这个占比挂在其中一个推荐的标记上：`portfolio_share=<两位小数>`（如 `0.16`，报告写"占组合约 16%"）；组合总值取不到时标 `rank_by_class_only`，意思是只按类别排序。**只转述百分比，不要报组合总值**（文件里只写取整后的占比，组合总值本身不写）。
4. **为什么不选**：每个未选策略一句理由和策略页链接，简要带过。
5. **步骤表**：七步表由运行时的常量算出，看数字时以报告为准。
6. **下一步命令、怎么带过去、限制**（必须同时讲，不要只给命令）。报告里有 `### 把 Delta 目标带到下一步` 小节、控制台每个带 Delta 的推荐下有一行 `带过去：`：**把这些命令原样转给用户**，不要自己改写档位、Delta 或参数，也不要自己换算。表里的 `ZZZQ` 是虚构 ticker，实际是用户给的那只：

   | 下一步 | 怎么带过去 | 限制 |
   |--------|------------|------|
   | 现金担保 Put：`/put-screen suggest --dte monthly` | 加 `--tickers ZZZQ` 只筛这一只；目标 0.15 时再加 `--delta 0.15`（目标 0.20 不用加） | `--tickers` 绕过 wiki 的 Avoid / 复核中状态；仍要求收盘价在 MA200 之上、到期前无财报，价差过宽时往外最多走到 0.10 或目标（取小者），所以远价外和"下行"的情形它**可能剔掉这只票** |
   | Bull Put 价差：`/spread-sim suggest ZZZQ` | 先 `suggest`，再 `open ZZZQ 0.15`（或更价外的 `open ZZZQ 0.10`） | 只有 0.20 / 0.15 / 0.10 三档，目标会就近放进这三档 |
   | Bull Call 价差：`/bullcall-sim suggest ZZZQ` | 先 `suggest`，再 `open ZZZQ 0.60`（或更便宜的 `open ZZZQ 0.50`） | 买方策略，净支出全亏的风险 |
   | 铁鹰：`/condor-sim suggest ZZZQ` | 先 `suggest`，再 `open ZZZQ 0.15` | 大涨对铁鹰是满额亏损 |
   | 备兑 Call：`/call-screen suggest --dte monthly` | 目标 0.15 时加 `--delta 0.15` | 它不接 ticker，扫全部持股，`--delta` 对这次扫的每只持股都生效；价差过宽时往外最多走到 0.10 或目标（取小者），可能不出这只票 |
   | Collar / 保护性 Put：`/collar-screen suggest` | **带不过去**：它不按 Delta 选，按现价 90% / 85% / 80% 三档列出 Put（Collar 的 Call 取零成本） | Delta 目标带不过去；对照报告里的"参考价位"，挑最接近的一档 |
   | 不做 / 继续持有 / 减仓 | 无，或 `/stock-review TICKER` | — |

   `/put-screen` 和 `/call-screen` 的 `--delta` 范围是 0.05–0.40、最多两位小数，默认 0.20；`/put-screen` 接 `--tickers`，`/call-screen`、`/collar-screen` 不接 ticker。

7. 提醒：工具只给策略方向和参考区间，**不选合约、不推荐具体档位**；样本局限（一年只是一个行情阶段，高低 IV 是对自己过去一年比，工具不预测方向）报告里有固定一节。

**特殊结论的说法**：
- 门槛出局（流动性不够）：说"不做期权建议"和具体哪一项没过，不要换个策略凑一个。
- 不看好：不出任何看涨策略；已有单账户 ≥ 100 股时只提示考虑减仓（`/stock-review`、`/stock-exit`）或用 Collar 锁下限（`/collar-screen`）；不足 100 股不提 Collar。
- 历史不足：不分类、不给策略、不算 IV 位置，文件仍会写。

**退出码 1（失败）**：脚本打印"错误：…（什么都没写）"。原样转述错误，并说明：
- **数据源连不上**（网络断了、Yahoo 被限流、IBKR 网关中途掉线）：整次运行中止，不写文件，**不会换别的数据源重试**。恢复后重跑。
- **错误提到 10197（竞争会话，IBKR 模式）**：同一个 IBKR 账户的实盘会话（手机 App 或 TWS）抢走了行情；退出实盘会话，或在账户设置里关闭行情共享，再重跑。
- 其他（行情数据不可用、找不到合约、设置缺失）：把错误给用户，不要自己改 `data/ibkr.env`。
- 注意区分：数据源**明确说没有期权数据**是门槛出局，退出码 0；"找不到合约"之类是缺数据，退出码 1。

**退出码 2（参数错误）**：把错误给用户，修正参数。

## Rules

- 只读、只建议：不下单、不碰账本和 `data/positions.md`；不写 `wiki/`、`outputs/`；只写 `data/strategy-picks/`（`.md`、`.json` 和同名 `.svg`，同日同票覆盖；写入失败时保留旧的一对文件）。
- 看法永远来自 wiki 或用户本人。退出码 3 时问用户，不替他选。
- 转述所有警告，不淡化"权利金薄""论点过期""代理"；不发明推荐，不把"粗略"的参考价位说成精确的行权价。
- 例子一律用虚构 ticker（如 ZZZQ）；不要在回复里引用用户的真实持仓、账户名或成本。报告和 JSON 里**有**精确的持股数据：Markdown 写持股股数、持仓行数和单账户最大股数，JSON 的持仓块写精确合计；没有账户名、成本和盈亏。所以这对文件只放在 gitignore 的私有目录 `data/strategy-picks/`，永远不进 `wiki/`、`outputs/` 或任何公开位置，也不要把股数抄进公开页。
- 美元数字都是每股或每 100 股的估算，不含手续费。
- 已知局限：平值 Put / Call 的 bid 为 0 时，工具一律当成报价陈旧，买卖价差这一项记"未验证"（不算出局），并给"流动性未验证（报价陈旧），盘中重跑"的警告；它不区分盘中还是休市。盘中跑出这条警告时，要提醒用户 bid 为 0 本身可能就是流动性差，不要当成门槛已过。
- 研究用途，非投资建议；最终用哪个策略、开不开仓由用户决定。
